# Map — Worktree, branch & cross-project linkage

Label: `wayfinder:map`

## Destination

A set of locked architectural decisions + a unified data model for *linkage* across nodeterm — worktrees, branch dependencies, and cross-project subagents — such that implementation needs no further design. Planning only: this map resolves decisions, not deliverables. The unified `Link` substrate is designed so a later "canvas-of-canvases" / drill-through rendering layer can compose on top of it without rework.

## Notes

- **Stack:** Electron + React + `@xyflow/react` canvas + Zustand stores; terminals are xterm.js over tmux (`nt-<nodeId>`). Core data model: `src/shared/types.ts` (`CanvasNodeState`, `Project`, `BridgeLink`). Renderer state: `src/renderer/state/`. Persistence: `<cwd>/.nodeterm/project.json`.
- **Skills every session should consult:** `/grilling` + `/domain-modeling` for design tickets; `/prototype` for the isomorphism; `/research` for fact-finding (stack tools).
- **Load-bearing existing mechanisms to lean on, not re-invent:** the canvas-switcher load effect (`Canvas.tsx:1743-1894` — the reusable primitive for switching the active node-set); the parking/adopt reparent (`TerminalNode.tsx:2279-2283, 3439-3475` — the existence proof for moving an xterm element between hosts without respawning); the co-attached modal terminal (`ModalTerminal` / kanban card modal — the precedent for a second viewer onto one tmux session); the hook-server routes (`/context-link/`, `/control/` — the agent↔canvas seam); `git worktree list` + `git.repoRoot` (already reachable).
- **Feasibility facts (verified):** the existing canvas/kanban `viewMode` is a *layer over a kept-alive canvas*, NOT a render-target swap — template for overlays, not for reparents. The reverse leg of the group↔canvas isomorphism (canvas→group embedding) and the cross-project canvas-of-canvases are **unassessed** → fog/prototype, not assumed cheap. The project-switch load effect *is* the reusable mechanism for the group→canvas leg.
- **Standing preference:** avoid dual-source drift (the codebase's own invariant). Where two representations could coexist (e.g. worktree group-binding + worktree-as-canvas), they are two *views* toggled by the isomorphism, not two parallel data models.

## Decisions so far

- [R01 — Stack-tool leverage evaluation](issues/R01-stack-tool-evaluation.md) — **git-town** recommended: topology is plain git config (`git-town-branch.<child>.parent`), drivable 1:1 from nodeterm's dependency links; local-first (explicit offline mode), MIT, no virtual-branch conflict. gh-stack secondary for GitHub-native Stacked PRs. Findings: `research/stack-tools.md`.
- [01 — Link & Endpoint data model](issues/01-link-endpoint-data-model.md) — **RESOLVED.** Unified `Link {id, kind:'context'|'lineage'|'dependency', source:Endpoint, target:Endpoint, meta}` replaces `bridges`+`ropes`; `Endpoint = node | xnode(projectId,nodeId) | branch(repoPath,branch)`. THREE kinds not two: `context`(←bridges, read-back) / `lineage`(←ropes, display-only, never context) / `dependency`(new, 03/04). Storage: all links on the SOURCE project (`Project.links`), cross-project = foreign `xnode` ref, lazy-prune unresolvable targets (Q-L1=a). CanvasMutation stays node-only; migration schema-versioned, preserves ids. Unblocks 03/04/05/06/09.
- [07 — Node-group↔canvas isomorphism](issues/07-nodegroup-canvas-isomorphism.md) — **RESOLVED.** `openNodeGroupAsCanvas(group)` = `setNodes` with the group's direct children promoted to root-space via `rootPosition` (workspace.ts:918), gated on a transient in-memory `DrillContext` (not persisted). **xterm continuity fog graduated favorably:** the drilled group's own terminals stay MOUNTED (RF keys nodes by id; the lifecycle effect is keyed on `respawnNonce`/`offscreenEpoch`, not position/parentId — no park, no re-acquire, no renderer host-jump); only SIBLINGS park via the existing 5-min primitive. So F11 (10) needs no overlay fallback. **Reverse leg fog graduated (trivial):** exit restores `parentId`/`extent` — one `setNodes`, no embedded preview (rejects dual-source drift). Viewport derived (`fitView` on entry, stashed parent viewport on exit), not persisted. Commits go to the owning project (merge drilled children back into full `project.nodes`). CanvasMutation unchanged. Unblocks 08/09/10.
- [02 — Repo-root Session grouping](issues/02-repo-root-session-grouping.md) — **RESOLVED.** `buildSessionList` returns `RepoGroup[]` (was `SessionGroup[]`); grouping = `repo → worktree-group → session`. Repo≡project COLLAPSES (`collapsedProject:true`) when exactly one project maps to a repo root AND `cwd===repoRoot`; splits (repo→project sub-bucket) when multiple projects share the repo or cwd is a subdir (Q7=a). `RepoGroup` key is `(machineKey, normWorktreePath(repoRoot))` — the load-bearing hazard: path strings match across machines, so an SSH-project and a local project on the same-looking path never merge. Unbound worktrees surface via the EXISTING `orphans` from `reconcileWorktrees` (no new poller — `useWorktrees` extended with a `repoRootByProject` map); orphans render as `AdoptableWorktreeRow`s, bind reuses `attachWorktree`/`worktreeFromEntry` (no dialog), "open" deferred until bound.
- [03 — Branch-dependency + stacked-diff (same-repo)](issues/03-branch-dependency-stacked-diff.md) — **RESOLVED.** Three first-class ops delegated to **git-town**: `sync` (rebase+merge-parent+restack-on-merge), `propose` (PR-per-branch), `ship` (merge+cleanup); nodeterm owns the config-write + link storage natively. A `dependency` link with `branch` endpoints maps 1:1 to `git config git-town-branch.<child>.parent <parent>` (written at link-create, unset at delete, via the existing `git()` executor — which routes over the SSH ControlMaster); nodeterm's links ARE the git-town lineage, no reconciliation. Execution seam = BOTH: a canvas-control verb (`link-branches`/`sync-stack`) for agents + a ↻ Sync button on `GroupNode`'s worktree chip for users (three thin `GitService` pass-throughs: `townSync`/`townPropose`/`townShip`). Render: dashed accent edge `child→parent` between the two hosting worktree group nodes (derived from `project.links`, never persisted); link survives at repo level (02) when a branch has no host. Worktree-rebase caveat handled: run in the OWNING worktree's cwd (branch is already HEAD → checkout is a no-op).
- [06 — Off-canvas link authoring surface](issues/06-off-canvas-link-authoring-surface.md) — **RESOLVED.** New `LinkTargetPicker` modal lists every OPEN project (read from `useProjects`, not React Flow — background projects work unloaded) as collapsible sections of their serialized nodes; auto-classifies a foreign-project pick as an `xnode` endpoint via `resolveEndpoint`; a Branch tab reuses `git.branchList`. This is the load-bearing new piece (no cross-project node picker existed). Entry points: node context-menu `Link to…`/`Links…` + hideable `🔗` header button (primary), mirrored in the **CardModal header** (two-views parity), read-only `Links…` in the sidebar, ⌘K node-scoped `Link to…`. Inspector `LinkInspectorPanel` (flyout) lists out/in links deduped, kind chip, endpoint display, optional `meta.purpose` subtitle, `×` delete via one `commitLinks` funnel (also drops the matching `bridge-*` edge). Links do NOT need a name — `kind` is semantic, `meta.purpose` optional. On-canvas `onConnect` stays the fast path for same-canvas `context`/`note` and writes via `commitLinks`; off-canvas picker is the ONLY path for `xnode`/`branch`/`dependency`/`lineage` (dashed derived edges, delete-only via inspector). One `commitLinks` + one `contextLink.setLinks` push keep all stores + main's link map in sync. Unblocks 04/05.
- [08 — Worktree-as-canvas](issues/08-worktree-as-canvas.md) — **RESOLVED.** Coexists with `data.worktree` group-binding (Q18=b): the binding is durable, the drill is a transient derived view (in-memory `DrillContext`), no migration, no new NodeKind, no dual-source drift. Since the group frame leaves the node-set when drilled, GroupNode's chrome is absent — the branch chip + Merge/Unbind/Remove move to a transient canvas-level header strip (outside `<ReactFlow>`'s z-trap), reusing `worktreeActionHandler` + `useWorktrees.refreshStatus` (visibility-gated, no new poller). **Refines 07:** `cwdForNewNodeIn` does NOT work unchanged while drilled (the group is absent from `nodesRef`, so the walk returns undefined) — the DrillContext reads `data.worktree.path` from the FULL `project.nodes` and passes it as `cwdOverride` (existing `addTerminal` funnel; `addAgent` needs the same param added — gap). parentId preserved via exit-before-commit: run the 07 reverse leg (re-nests ALL drilled children incl. new ones with `parentId=groupId`) before `commitActiveToStore` — no parallel merge code. Sidebar: bound worktree row calls `openNodeGroupAsCanvas` (`pendingDrillRef` mirrors `pendingFocusRef`); unbound runs 02's bind first. Ordering: bind(02)→drill(08)→isomorphism(07).
- [04 — Cross-repo npm dependency link](issues/04-cross-repo-npm-dependency-link.md) — **RESOLVED.** Cross-repo `dependency` target is `{ref:'xnode',projectId,nodeId}` (B's branch-hosting node), NOT `branch`-with-projectId — the `branch` endpoint exists solely to feed git-town topology (03), which has no cross-repo meaning (A and B share no git). The link is **declarative-only** (drives nothing automated — no git-town, no auto-spawn); 05's spawn is an *action enabled by* the link, creating a separate `lineage` link (Q15=b — collapsing "depends on" with "has spawned" is rejected). Render: strictly off-canvas in 06's `LinkInspectorPanel` — no canvas edge on A or B (a cross-project edge is 05's projection / 09's canvas, not 04's). B-must-be-open: `xnode.projectId` resolves via `getProject()`/`openFolderProject` cwd-dedupe; if B is absent/closed, the target lazy-prunes (01's Q-L1 invariant) as a muted inspector row. npm auto-detection = FOG: if pursued, trigger on project open scanning A's `package.json` deps against open projects' `package.json` `name` fields (NOT folder names — the hazard), suggest-only via 06's pre-targeted picker.
- [05 — Cross-project subagent spawn + projection](issues/05-cross-project-subagent-spawn-projection.md) — **RESOLVED.** A renders a **derived ephemeral node** (new render-only `type:'xproject'`, absent from `NodeKind` so `flowToNodeStates` never serializes it) merged at the `<ReactFlow>` prop like subagent/loop cards. A persists ONLY the `lineage` Link; the node is recomputed each render from a cross-project read of B's `Project.nodes` in `useProjects` (B is single source of truth — no copy). **Co-attach:** projection mints `viewerId=xproj-<BprojectId>-<nodeId>-<rand>`, co-attaches via `join()`'s `SubKey` ledger as a distinct subscriber of B's `nt-<nodeId>` (votes its own size), passes B's project context (persistKey/ownerProjectId/cwd/agentId/accountId/sshRemote/requireRemote from B), writes `CO_ATTACH_MOUSE_SEQ` when `res.coAttachMouse` set, paints via `create-screen`/`seedPaint`; B's session absent → placeholder (refuses to spawn — `requireRemote` precedent). **Visual:** `.xproj-node` opacity 0.72, dashed outline in B's project color, B-badge pill, secondary jump (`openNodeGroupAsCanvas`/project-switch + `focusNodeById`); primary = the live co-attached xterm. **Spawn:** `open-agent --project <cwd-or-id>` resolves via `openFolderProject` and REFUSES if no match (no silent local fallback); node written into B's `Project.nodes` via `setProjectData` inheriting B's `defaultAccountId`/`defaultPermissionMode`/`cwd` (not A's). **Links:** spawn auto-creates the `lineage` link only; `dependency` authored separately off-canvas (06), spawn may offer both. Communication via existing `get-linked-context` skill + `/context-link/` route (no new injection). Remote spawn = fog.
- [09 — Canvas-of-canvases](issues/09-canvas-of-canvases.md) — **RESOLVED** (fog-gate lifted: 01+07 settled). Cross-project drill IS the existing project switch (load effect 1746–1895, `setActive`), triggered from a `data.projectRef` group; new `DrillContext` variant `{kind:'project-ref';projectId}` distinct from 07's `{kind:'group';…}` — no merge-back needed (commits land in the target project via `commitCanvas`), no `cwdOverride` (target's full `project.nodes` loads). **Project-as-node = `kind:'group'` + new `data.projectRef?:{projectId}`** on `CanvasNodeState` (beside `worktree?`) — NO new `NodeKind` (sidesteps the feasibility "large schema change"); chosen over a standalone `xnode` link because a project-ref must RENDER as a frame; `xnode` links stay for cross-project *node* relations. **Submodule auto-link:** `dependency` kind (A depends on the submodule); new `listSubmodules` via the `GitExecutor` pattern (`worktree-ops.ts` template) exposed as `submoduleList` IPC; trigger on meta-canvas open (not every project open); open submodule → auto-create `dependency` link + project-ref group; unopened → derived ghost suggestion (never persisted), click runs `openFolderProject`. **Meta-project is a real `Project`** — preserves "everything is a Project," reuses `commitCanvas`/`workspace.save`/load effect unchanged (no dual-source drift); dangling `data.projectRef` (deleted project) → lazy-prune + greyed "unavailable project" node mirroring the unavailable-tab pattern, re-resolved each load, NOT auto-deleted (reopening the folder restores the same cwd-derived id).
- [10 — F11 focus mode = `openNodeAsCanvas`](issues/10-f11-focus-openNodeAsCanvas.md) — **RESOLVED.** Near-free given 07: new `{kind:'node';nodeId;projectId}` DrillContext variant (NOT a synthetic single-child group — the honest representation makes the commit-merge trivial: replace one node in the full array, the degenerate case of 07's group-child merge). 07 already proved the reparent keeps the terminal mounted (RF id-keying; lifecycle keyed on `[respawnNonce,offscreenEpoch]`), so NO `ModalTerminal` overlay fallback needed. **Keybinding:** F11 + `preventDefault` on desktop (Electron `before-input-event` intercept claims it before the Linux fullscreen accelerator, mirroring the ⌘0 steal; no collision with zoom/project-jump `Digit*` chords); ⌘K "Focus node" is the platform-agnostic path and the SOLE entry point in Server Edition (browser F11 is uncontrollable fullscreen). **Exit:** Esc (outside xterm — terminal owns Esc for agent interrupt) + F11-toggle; reverse leg is 07's (restore full `project.nodes` + stashed viewport). **Per-surface:** canvas nodes drill (primary); kanban card modal = no-op (already a focus surface — path is the card's ↗ "open on canvas" then F11); Sessions sidebar stays `focusNodeById` (navigation, not focus — two different things).

## Not yet specified

<!-- in-scope fog you can't ticket yet; graduates as the frontier advances -->

- **xterm/renderer tolerance for a canvas-switch reparent.** **Resolved (07):** favorably — the drilled group's own terminals stay mounted (RF id-keying; lifecycle effect keyed on `respawnNonce`/`offscreenEpoch`, not position), so no live-switch tolerance is even asked of the renderer. Only siblings park. No fork; F11 needs no overlay fallback.
- **The canvas→group reverse leg of the isomorphism.** **Resolved (07):** trivial — exit restores `parentId`/`extent` via the same `setNodes`; no embedded preview (would re-introduce dual-source drift).
- **Cross-project canvas-of-canvases.** **Resolved (09):** a meta-project (a real `Project`) whose `kind:'group'` nodes carry `data.projectRef:{projectId}`; drill = the existing project switch (`DrillContext {kind:'project-ref';projectId}`). No new `NodeKind`. Submodules auto-link as `dependency` links + project-ref groups (open ones; unopened → ghost suggestion). Dangling refs lazy-prune to greyed "unavailable project" nodes. Fog-gate lifted once 01+07 settled.
- **npm-link / `file:` auto-detection for the cross-repo dependency link.** Auto-detecting that project A depends on project B's local npm wiring is plausible but unassessed. The explicit off-canvas authoring path is committed; auto-detection is a graduation candidate off ticket 04.
- **Remote cross-project spawn (local→remote, remote→remote).** The committed spawn mechanism (extend canvas-control `open-agent --project`) works local→local via the existing seam; remote variants are fog.
- **Native tool-injection ("plugin") upgrade.** If the skill + route communication path (Q16=a) proves too clunky for agents to discover/use, a first-class tool/MCP injected into the agent's config is the upgrade — net-new seam, agent-specific. Graduation candidate off ticket 05; not an upfront commitment.
- **Which stack tool to leverage** for same-repo stacked-diff operations (graphite / gh-stack / gitbutler). A pure research question → ticket R01. **Resolved (R01): git-town.**
- **File-change coordination between linked agents.** Whether linked sessions benefit from real-time coordination of which agent touches which files (to avoid same-file edits). Probably not worth the squeeze in practice — deferred as low-priority fog, not a ticket unless a need surfaces.
